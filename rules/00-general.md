# Regole generali (valgono per tutti i progetti)

- Rispondi in italiano; codice, identificatori, commenti nel codice e messaggi di commit in inglese.
- Prima di modificare codice, leggi i file coinvolti e segui le convenzioni già presenti nel progetto. Le convenzioni locali vincono sulle preferenze generiche.
- Fai modifiche minime e mirate al task. Niente refactoring non richiesti, niente riformattazione di file interi.
- Se il task è ambiguo o tocca un contratto pubblico (API, eventi, schema DB), fermati e chiedi prima di procedere.
- Ogni modifica funzionale va accompagnata da test o dall'aggiornamento di quelli esistenti.
- Non introdurre nuove dipendenze senza dichiararlo esplicitamente e motivarlo.
- Per convenzioni specifiche di stack (Spring, Angular, OpenAPI, test) usa le skill aziendali corrispondenti.
